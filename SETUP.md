# RS on the Go LLC website

The public site uses static HTML, CSS, and JavaScript. Netlify serves `public`, handles quote and review submissions, and runs the owner functions. The build type-checks the TypeScript modules and bundles the admin entry point and lazy-loaded maps.

## Code layout

- `src/admin/index.js` coordinates sign-in, navigation, and workspace data. `src/admin/enquiries/` owns the typed enquiry list, detail views, and drafts. `src/admin/website/editor.js` owns website editing and preview. Shared DOM form controls live in `src/admin/components/`.
- `src/domain/jobs/` owns the shared enquiry types, Eastern calendar dates, job-number rules, search, and CSV formatting. Browser modules and Netlify handlers use those same rules. `netlify/lib/jobs/` loads the workspace inbox and assigns job numbers with conditional storage writes.
- `public/assets/` holds existing browser components and styles. The admin page loads the generated `admin.bundle.js`. Edit source modules and run `npm run build` to refresh that bundle. Use Node 24 and run `npm run check` for strict TypeScript checks and automated tests.

The local owner workspace is available only in Netlify Dev on a loopback hostname. Data is saved under `.netlify/owner-preview/`, which is ignored by Git. Preview forms save locally and show a notice that no email was sent. Production forms continue to use Netlify Forms.

For live local address lookup and routing, put `GEOAPIFY_ROUTING_KEY` in a local `.env` file. Without it, city selection, manual locations, and quote requests remain available. The Geoapify API still receives lookup requests when configured. The static Python preview can display the pages but cannot run admin functions or save submissions. [Netlify Dev functions](https://docs.netlify.com/api-and-cli-guides/cli-guides/manage-functions/#invoke-functions-while-running-netlify-dev).

Run `npm run check` for the regression checks. With Netlify Dev running, `node tests/local-integration.mjs` tests local publication and access protections using clearly labeled test records, restores website settings, and unpublishes its test review.

The quote form has one address-mode button for both locations. Manual entry hides the search inputs and shows separate U.S. pickup and drop-off fields; switching back restores the previous search entries. The transition respects reduced-motion preferences.

The workspace opens to Overview with request counts, recent enquiries, a job map, a compact calendar, and the next items to handle. Enquiry details use Route & load, Customer, and Notes & status tabs. Website settings start collapsed; opening a section shows its editing fields and a live draft preview. Full preview supports desktop and mobile sizes. Review actions live in a dropdown beside each card’s preview. Lucide icons are vendored in `public/assets/admin-icons.svg`.

The authenticated workspace uses a floating, translucent sidebar with the brand, a white selected row, and a red active icon. A shared matte-glass highlight uses a single transform-only glide between navigation items, retargets from its rendered position during rapid clicks, and realigns when switching to the horizontal mobile layout. Motion has no overshoot, shimmer, or icon bounce; the selected row and red icon use restrained depth. Reduced-motion preferences use an immediate highlight change. A compact light header holds the website link and profile controls; each section has a single main page title. On mobile, navigation becomes a compact sticky glass bar below the branded header. These styles are scoped to the workspace and preserve the login design. Solid surfaces provide a fallback when backdrop blur is unavailable. Save confirmations use a compact dismissible notification instead of shifting the page down with a banner. They expire after eight seconds, pausing while hovered, focused, or in a background tab. Errors stay visible until dismissed. Mobile notifications sit near the bottom; header actions remain available as labeled icon buttons. Motion respects reduced-motion preferences.

## Dispatch walkthrough

1. Open **Admin → Enquiries** or select a new enquiry from the notification bell. Use the job number when discussing a request with another dispatcher.
2. Check **Route & load**, then use **Customer** to call or email. Once the customer agrees, record the price, status, and confirmed pickup time in **Notes & status**. Check **Overview → Calendar** for the scheduled job.
3. In **Reviews**, read feedback directly and select **Show on homepage** for reviews the customer has allowed you to publish. In **Website**, use the full preview to check business information or photos before publishing changes.
4. To check what customers see on a phone, open the homepage, expand a service, and select its quote link. Use the local preview for practice submissions.

## Day-to-day admin tools

- The optional **Workspace assistant** accepts typed questions and follow-ups about the admin and public website. Its bubble stays hidden unless `RS_ASSISTANT_GROQ_FREE_KEY` is configured in Netlify's production Functions environment, or in the ignored local `.env` for loopback testing. Use a dedicated Groq **Free** organization and keep billing disabled there. There is no other provider or paid fallback. Keep the key server-side. The site sends a role-specific guide, selected published business information, and up to three prior conversation turns. The site stores no chat transcripts and applies a quota of 20 questions per account and 60 per workspace per UTC day. Groq can apply lower free quotas. Avoid entering customer details or credentials. [Groq quickstart](https://console.groq.com/docs/quickstart) · [Free plan and billing](https://console.groq.com/docs/billing-faqs)

- The job map shows saved pickup/drop-off coordinates or approximate city positions from the bundled Gazetteer. Manually entered street locations are not guessed. Choose a request and select **Show driving route** for the existing Geoapify mileage/time preview. Map backgrounds use OpenFreeMap through MapLibre and Leaflet; they require no map API key. The same background is used in public quote previews. [OpenFreeMap integration](https://openfreemap.org/quick_start/).
- The calendar distinguishes the customer's requested date from a confirmed pickup date. Set the confirmed pickup date/time in **Notes & status** after agreeing it with the customer. Pickup times and received-date filters use Eastern time. Follow-up dates and shared reminders appear alongside pickups. Reminders can be edited, completed, and reopened; they do not send email, SMS, or browser notifications.
- **More filters** in Enquiries provides received-date filters, sorting, and an owner-only CSV export of the filtered records. Exports include private notes and contact details; spreadsheet formula prefixes are escaped.
- Enquiries shows 25 results at a time. Filters, job links, and CSV export cover the full matching history. The dashboard still loads the full set for its calendar, counts, and maps. Use production timings to decide when to move the intake history to an indexed queue or database.
- Each enquiry has a job number such as `RS-202611-VEH-0001`. `RS` identifies the company, `202611` is the Eastern year and month the quote arrived, `VEH` identifies scheduled vehicle hauling, and `0001` is the sequence for that service and month. The other service codes are `EQP` (equipment), `FRT` (freight), and `GEN` (general or older uncategorized jobs). A missing received date uses `UNDATED`. The sequence expands beyond four digits when needed. Search by job number, copy it or its private admin link from the enquiry, or find it in the CSV.
- Verified quotes get a number the first time the inbox or export loads them. Existing quotes receive numbers from oldest to newest within the first batch. A late import receives the next available number in its original month and service; existing numbers never shift. The original submission ID still connects saved notes, schedules, version history, and appointments. Numbers use the raw submission's received date and service, so later admin edits never change them.
- Open **Settings**, or select your avatar in the header, to change your display name, private phone, job title, or profile photo. JPEG, PNG, and WebP files up to 5 MB are cropped in the browser to a 256px square JPEG; the function accepts only bounded JPEG data. Each account's profile is stored separately and never appears in the public site response. Settings also saves a personal timezone and 12/24-hour clock format, with a live preview and a device-timezone shortcut. These preferences apply to the dashboard clock, header date, and received/updated timestamps. Bookings, reminders, and received-date filters retain Eastern business dates; pickup times can display in 12/24-hour format without changing their saved value. Save and discard controls preserve unsaved drafts while navigating, and stale revisions cannot overwrite newer saves. Sign-in email and access remain managed by Netlify Identity.
- In **Website**, open **Opening screen**, **Business & contact**, or **Job photos** and choose **Change image**. Drop one photo onto the preview or upload area, or use **Browse files**. The picker accepts JPG, PNG, and WebP originals up to 12 MB. Add an image description, choose its alignment, and select **Use image** to update the draft. **Full website preview** shows the result; **Publish changes** makes it public. **Restore original** and **Discard changes** are available before publishing.
- **Image library** lets the owner reuse uploaded photos and the three original site photos. Uploads are resized to at most 1920px and converted to WebP, with a smaller responsive version. The server decodes them again and strips embedded metadata. Unpublished images require owner access; public image URLs work only while referenced by published website settings. Removing a photo from the website keeps it in the private library. There is no permanent-delete action.
- Image uploads and previews work on mobile using **Browse files**; no desktop-only restriction is needed. The picker body scrolls while its save and cancel controls remain visible. Profile photos remain separate from the website image library.
- **Recent changes** is a collapsed list of saved job, reminder, review, and website changes. Each record keeps up to 50 recent events, saved in the same conditional write as the change. This is operational history, not an immutable compliance audit log.

`node tests/operations-integration.mjs` checks local scheduling, reminders, profile validation, CSV downloads, storage revisions, and public/private separation. It restores the previous profile, closes its own labeled test quote, and completes its test reminder.

`node tests/settings-integration.mjs` verifies local preference persistence, invalid timezone rejection, role isolation, and stale-save protection, then restores the original profile and preferences.

`node tests/media-integration.mjs` checks real local image upload, format validation, responsive images, and publication. It restores the previous website settings and leaves one clearly labeled private test image in the local image library. These tests use Netlify Dev and do not deploy or consume build credits. Native image processing uses Sharp; the upload function's external dependency is configured in `netlify.toml`.

## Personal workspace customization

Settings starts with **Your profile**, followed by **Date & time**, **Color theme**, and **Your workspace**. The four personal themes are RS red, Graphite, Ocean, and Forest. Theme and preset cards use native radio controls with custom styling and keyboard support; themes affect only the authenticated admin workspace.

On desktop, Compact, Balanced, and Spacious have small white-panel previews. Each preset owns spacing, columns, and text size, with no separate fine-tuning controls. Legacy layout/font overrides remain readable in the stored schema but no longer override a preset. At 1100 CSS pixels and below, mobile always uses one column, Balanced spacing, standard text, and the default panel order. Desktop preset controls are hidden there, and saved desktop choices return on wider screens. Themes and panel visibility remain personal on every screen. At phone widths, navigation uses one horizontally scrolling row; the selected section scrolls into view and the glass highlight stays aligned as the row moves.

**Panels & arrangement** controls which Overview panels appear and their desktop reading order. Each row includes a gray thumbnail, short description, and numbered **Position** selector. Choose 1 for first, or any other position, to insert that panel and shift the others automatically. The selector retains keyboard focus after a move and announces the resulting position. Unchecked panels retain their positions; permission-restricted panels cannot be edited. The **?** button explains the controls with a shown/hidden example; Escape or Close returns focus to the button. Hiding every panel leaves a clear route back to customization. The position selector follows [W3C's G219 technique](https://www.w3.org/WAI/WCAG22/Techniques/general/G219.html), which includes choosing a drop position from a menu as an alternative to dragging.

Theme, preset, and panel choices remain drafts until **Save changes** succeeds. The workspace keeps its saved appearance while editing, after a failed save, and when visiting other sections. Returning to Settings keeps pending selections; **Discard changes** restores the last saved profile, time, and workspace choices. **Restore workspace defaults** selects defaults in the workspace draft; it preserves the user's profile and time settings and still requires Save. Preferences live in the authenticated account's private profile record and use the existing revision check. Visibility is not an access control: server roles and permission checks continue to apply.

The gray rectangle was the desktop header's full-width frosted surface, rather than public website content. The header now contains only the floating controls. The review also improved muted-text contrast, responsive navigation at larger text sizes, section-change focus/scroll behavior, lazy loading for hidden maps, and the settings clock's back/forward-cache lifecycle. The public site's design is preserved.

### Extending the customization system

- `public/assets/workspace-config.js` is the shared, versioned schema and panel/preset/theme registry. Add a panel entry with a stable ID, title, description, DOM selector, and optional required permission, plus its normal panel markup. Older saved orders automatically include newly registered panels. Older profiles without a theme resolve to RS red. `effectiveWorkspace` derives the fixed mobile presentation without modifying saved desktop preferences.
- `workspace-layout.js` applies saved preferences to existing panel nodes and responds to breakpoint changes. It moves real DOM nodes, preserves component state, and keeps keyboard reading order consistent with the visible order. `workspace-customizer.js` owns preset previews, draft radio choices, and the help dialog. `workspace-customization.css` owns scoped typography and spacing; `workspace-themes.css` owns personal color tokens, theme-card styling, thumbnails, and responsive controls. `admin-shell.css` and `admin-navigation.js` own the scrolling navigation and its highlight.
- `admin-settings.js` composes customization with the profile form and manages drafts. `netlify/lib/profile.mjs` validates preferences using the same schema and saves through the authenticated user's profile key; user-provided IDs, email, and roles do not select an account or alter access.
- Keep stable panel IDs when renaming labels. Add schema migrations in `resolveWorkspace` when a future version needs them. Test migrations, permission filtering, hidden-panel recovery, keyboard focus, and save/reload before introducing additional controls.

The design follows [NN/g's customization guidance](https://www.nngroup.com/articles/customization/) on useful defaults and optional controls, plus W3C guidance on [alternatives to dragging](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements) and [reflow at narrow widths](https://www.w3.org/WAI/WCAG22/Understanding/reflow). These are design inputs, not a claim of a complete WCAG conformance audit.

## Deploy from GitHub

1. Push the branch containing the redesign to GitHub. In Netlify, import the existing RS on the Go website repository from GitHub and select that branch.
2. Leave the base directory blank. The build command is `npm run build` and publish directory is `public`, configured in `netlify.toml`. Use Node 24.
3. In the Netlify project’s **Forms** tab, enable form detection and redeploy. Check that Netlify lists two forms, `quote-request` and `customer-review`. [Form setup](https://docs.netlify.com/manage/forms/setup/).
4. Choose one quote alert method in **Email and reviews** below. Add a native review notification separately if desired. [Form notifications](https://docs.netlify.com/manage/forms/notifications/).
5. Submit a test quote and a test review on the Netlify URL. Verify that each opens its confirmation page, appears in the Forms dashboard, and reaches the intended inbox. Check that `/reviews.html` redirects to `/reviews/`.
6. Once the site and forms pass those checks, add `rsonthegollc.com` under **Domain management** if you want to keep the existing domain. Follow the DNS instructions Netlify shows for the project. If the domain also handles business email, preserve its existing mail-related DNS records during the website move. [Custom domains](https://docs.netlify.com/manage/domains/get-started-with-domains/).

The production build uses the primary HTTPS origin reported by Netlify or an explicit verified `RS_CANONICAL_URL` set in the production build environment. It emits canonical page URLs, a sitemap, a sitemap declaration in robots.txt, and Organization metadata using the public business name, phone, and Charlotte service base. Preview builds omit these generated files. Check the primary domain and contact details before submitting the sitemap to Search Console. ## Email and reviews

### Gmail in the owner workspace

The owner’s **Email** tab links a verified Gmail or Google Workspace address. Search queries go to Gmail and can return conversations outside the inbox. Google sign-in for the admin uses Netlify Identity.

1. In Google Cloud, configure the consent screen and create an OAuth client of type **Web application**. Request the `openid` and `email` scopes. If the consent screen is in testing mode, add the intended account to its test users.
2. Add the exact authorized redirect URI `https://YOUR-ADMIN-DOMAIN/.netlify/functions/workspace-email`. Use the same origin, with no trailing slash, in `RS_GMAIL_ORIGIN`. For localhost, register a separate development client with `http://localhost:8888/.netlify/functions/workspace-email` and use `http://localhost:8888` for its origin.
3. Set `RS_GMAIL_CLIENT_ID`, `RS_GMAIL_CLIENT_SECRET`, and `RS_GMAIL_ORIGIN` in Netlify's production Functions environment and deploy. For local testing, set the development values in the ignored `.env` and restart Netlify Dev.
4. Sign in as the owner, open **Email**, and select **Link Google account**. Choose your Gmail or Google Workspace account. The tab shows the linked address and lets you disconnect it.

To enable the inbox, turn on **Gmail API** in the same Google Cloud project. Add `https://www.googleapis.com/auth/gmail.readonly` under **Google Auth Platform → Data Access** and add the linked address to **Audience → Test users** while testing. Set a unique server-side `RS_GMAIL_TOKEN_KEY` for each environment using 32 random bytes encoded as base64url. The local preview loads it from the ignored `.env`. In production add it to Netlify's Functions environment and redeploy.

In **Email**, select **Connect Gmail inbox** for a new account or **Enable read-only inbox** for the existing linked account. Choose the intended Gmail account and approve read access. Google treats the read-only Gmail scope as restricted. Review Google’s verification and security assessment requirements or applicable exceptions before using it in production. External apps in Google’s **Testing** mode normally need authorization again after seven days. [Gmail API scopes](https://developers.google.com/workspace/gmail/api/auth/scopes) · [Token expiration](https://developers.google.com/identity/protocols/oauth2#expiration)

Add `https://www.googleapis.com/auth/gmail.send` under **Google Auth Platform → Data Access** for the same project. In the connected workspace, select **Enable sending**, choose the linked account, and approve the send permission. The owner can then compose messages and reply to conversations. Gmail delivers each message and shows it in **Sent**. The admin automatically saves one encrypted draft per owner and linked account, including files and reply details. Select **Save draft** for an immediate save and check the status before closing the browser. Compose restores the draft after signing back in. Sending or discarding clears the saved draft. Keep the token key available to recover encrypted drafts. The upload limit is 3 MB total across up to 10 files per message. Use **Open Gmail** for larger attachments. [Gmail sending guide](https://developers.google.com/workspace/gmail/api/guides/sending) · [Netlify Functions limits](https://docs.netlify.com/build/functions/configuration/)

The workspace fetches conversations from Gmail on demand. The reader preserves basic formatting and opens web links in separate tabs. It shows supported embedded pictures and loads external images by default. Owners can turn off automatic external images in the account menu. The **Attachments** view searches for messages with files, and the reader shows received filenames and sizes with an **Open in Gmail** link.

The private owner record holds the encrypted Gmail refresh token. Changing the token key requires reconnection. Disconnecting removes the stored grant and attempts to revoke it through Google. For outgoing messages, the private store keeps a bounded record of request fingerprints and delivery receipts for retry protection. Gmail holds the messages and attachments. [Google OpenID Connect setup](https://developers.google.com/identity/openid-connect/openid-connect)

### Notification email

For immediate verified quote alerts and optional pickup reminders, set the Functions environment variables in `.env.example` on the production Netlify project. Use a send-only Resend key, a sender on a verified domain, and the inbox authorized to receive alerts. Enable `RS_QUOTE_EMAILS` and/or `RS_PICKUP_EMAILS` with the value `true`. A Netlify verified Forms event queues a quote alert. It sends at most 25 distinct quote alerts per Eastern day. Extra quotes still appear in Enquiries. From 8 a.m. through the end of each Eastern day, the scheduled function looks for the next day's confirmed pickups. The first email summarizes known pickups. Later scans group newly added pickups into follow-up notices. Closed jobs stay out of future scans. The calendar reflects cancellations. Emails include a dashboard link and omit customer details. Retries use a stored delivery record and a stable Resend idempotency key. If you only want quote email without configuring Resend, choose a Netlify **Forms → Submission notifications** email for `quote-request` instead. Enabling both methods would send two alerts. [Netlify Forms events](https://docs.netlify.com/build/functions/trigger-on-events/#form-events) · [Scheduled functions](https://docs.netlify.com/build/functions/scheduled-functions/) · [Resend send API](https://resend.com/docs/api-reference/emails/send-email).

The public quote and review routes use validated, bounded submissions at the normal confirmation paths. A burst limit of 20 requests per IP and domain per minute applies to those paths, and the quote form keeps answers on errors. Netlify's own spam filtering and the existing honeypot still apply at intake, including equivalent submissions posted to other paths. Check the Spam list if a real request is missing. Existing Geoapify function limits protect lookup and routing capacity. [Netlify spam filters](https://docs.netlify.com/manage/forms/spam-filters/) · [Netlify rate limiting](https://docs.netlify.com/manage/security/secure-access-to-sites/rate-limiting/).

Owners see workspace quote email counts in **Enquiries**. The panel distinguishes sent and pending emails, failed deliveries, and quotes skipped at the daily limit. It also shows yesterday’s missed count when applicable. These figures cover the Resend-backed workspace notifications.

### Original submission backups

Generate a separate 32-byte base64url key and set it as `RS_BACKUP_KEY` in Netlify’s production Functions environment. Keep a secure copy of the key separate from downloaded archives. Use a different key in the ignored local `.env` for testing. The production schedule runs daily at 08:20 UTC. Owners can also open **Settings → Submission backups** and select **Back up now**.

Choose a saved copy to download its encrypted archive or restore missing submission rows into the owner workspace. Restore preserves the original submission IDs and timestamps. Existing Netlify rows take priority, dispatch notes stay linked to their IDs, and review publication requires the existing consent and owner workflow. The panel lists the latest 30 copies. Copies are stored in Netlify Blobs, so retain separate encrypted downloads for protection against loss of the hosting account. [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) · [Scheduled functions](https://docs.netlify.com/build/functions/scheduled-functions/)

Netlify handles website submissions and can send notifications to the inbox you choose. If the public contact address changes, update the default address in `public/assets/business-defaults.js` and the contact links in `public/index.html` and `public/privacy/index.html`.

Incoming reviews live in Netlify Forms. The owner’s Reviews screen publishes or unpublishes consenting feedback without a code deploy. The public endpoint returns only public names, original text, ratings, and dates. It keeps publication decisions and the public review list in a single revision-controlled record. The homepage has three review slots, managed at the top of Admin **Reviews**. New selections are added in slot order. Older lists keep the first three visible and leave the rest available in Admin. The existing `public/assets/reviews.json` is a fallback until the first admin publication record exists. If the old website received reviews or quotes, export them from the previous provider before retiring it.

Change the review field’s `maxlength` in `public/reviews/index.html` to adjust the form’s 800-character limit. Update the fallback hint beside it to match. The counter reads the field limit automatically. Homepage review cards use `reviewPreviewLength` in `public/assets/site.js` for their collapsed preview, and the feedback box uses `max-height` in `public/assets/site.css`.

## Activate the owner workspace on the live site

The admin login at `/admin/` uses the RS on the Go red, charcoal, and white split-screen design with a text-only welcome panel. It accepts a typed email (including Gmail) and the **website account password**, or an optional username alias. It never asks for the user's Google password. The **Login with Google** button uses Netlify Identity OAuth and returns through the existing callback handler. Enable Google under **Identity → Registration → External providers** and keep registration invite-only. Assign an authorized account its `owner` or `staff` role; Google sign-in alone does not grant workspace access. [External provider setup](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/registration-login/#external-provider-authentication).

For a username login, set `OWNER_LOGIN_USERNAME` and `OWNER_LOGIN_EMAIL` as Netlify environment variables with Functions access. The latter must be the invited Identity account's email. Both username and email login verify that account's existing password and role. The alias is case-insensitive and resolved only on the server; it is not a profile display name. Leave these variables empty for email-only password login. Future staff can use their own emails without sharing the owner's credentials.

**Forgot password?** opens a separate form that accepts the same email or username. It gives a generic confirmation for unmatched accounts and never exposes the email behind a username. Use `/admin/` as the invitation and password recovery landing path. Google-only accounts should use Google sign-in.

In Netlify Dev, `/admin/?login=preview` shows the login design without automatically opening the local workspace. Its **Open local workspace** link returns to the existing local test dashboard. The preview parameter never grants access on a hosted domain. Real Identity login, Google redirects, invitation acceptance, and recovery email delivery must be verified on the configured Netlify site; local rendering does not verify those services.

1. In Netlify Identity, enable invite-only registration and invite the owner. Give that user the `owner` role in app metadata. The invitation and recovery links should return to `/admin/`. The owner sets their own password through the invitation. The application has no public signup endpoint.
2. Set `NETLIFY_FORMS_TOKEN` for production Functions only. Use a token from a Netlify account permitted to read this site’s form submissions. The site ID is read from `SITE_ID`, or from `NETLIFY_SITE_ID` when explicitly configured. Hosted previews keep an empty Forms inbox because Netlify Forms submissions belong to the whole site. Use a separate staging project for hosted checkout of the full quote-to-inbox flow.
3. Hosted previews use a separate `rs-owner-sandbox` Blobs namespace. Production preserves the older release's namespace mapping. On a normal Netlify runtime that is `rs-owner-preview`, despite its legacy name. If a previous production setup explicitly supplied `CONTEXT=production`, its existing data may be in `rs-owner-production`. Check the live namespace before setting the optional `RS_OWNER_STORE` override. Every hosted admin action checks the signed-in account and role. Owners manage all tools. Staff manage enquiries, dates, reminders, and personal settings. [Netlify runtime variables](https://docs.netlify.com/build/functions/environment-variables/#netlify-read-only-variables) · [Identity roles](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/manage-existing-users/).
4. Deploy the finished batch once. Sign in as the owner and verify that enquiries load. Check a staff account's permitted and forbidden actions and an anonymous session. Publish then unpublish a consenting test review, check public fields, and verify that website settings persist.
5. Verify the recipient inbox, business facts, service coverage, and operating hours with the owner. Send one controlled live quote and review and confirm receipt in Forms and the intended inbox. Local tests do not verify live email delivery.

Owner edits use storage revisions so a stale tab cannot overwrite a newer save. Enquiry statuses and notes are private. Production data uses Netlify Blobs with strong reads and conditional writes. Local tests use atomic filesystem writes and exclusive locks. Public settings exclude owner metadata. Runtime usage still counts toward the hosting plan even though content edits do not trigger deployments.

**Enquiries → Notes & status** saves the agreed USD price using integer cents and includes it in the private owner CSV. The record header offers call, text, and email actions when contact details are usable. **Version history** in the enquiry editor and website publish bar shows up to 20 previous editable versions to the owner. Review the version before restoring. Restoring website content publishes it and keeps the displaced version. History covers accidental edits from this release onward. For broader disaster recovery, keep periodic export copies and independent backups of production site records and media.

Hosted admins have a 30-minute idle limit and a 12-hour maximum session. Workspace access requires the verified Identity account plus a separate secure, HttpOnly workspace cookie. The API checks deadlines on protected requests. The browser warns before closing the workspace, and a user can select **Stay signed in** while the idle session is valid. This cookie is set during admin sign-in only. Public quotes and reviews do not need an account or a new session cookie. Expect existing hosted admins to sign in again after the upgrade. Test password, Google, and recovery flows in the hosted environment because local preview bypasses Identity.

Netlify Forms plus Blobs can support this workload without a separate database. Forms remain the source of incoming quotes and reviews. The current inbox still loads all pages, and the daily digest reads the saved enquiry records. Track inbox load time, notification volume, function timeouts, and job count. As those grow, use a managed PostgreSQL database for a paginated enquiry inbox, indexed pickup dates, and a transactional notification queue. Keep media in object storage.

The website editor manages the homepage photo, contact photo, and two job photos with captions. New images are uploaded through the authenticated function into Netlify Blobs; publishing image changes does not require a code deploy, though storage and function traffic count toward the hosting plan. Staff cannot upload, browse the image library, or publish website images. Fleet tracking, payroll, payment analytics, bulk record deletion, API-secret editors, and user-account CRUD are intentionally outside this single-operator workspace. Account invitations, disabling accounts, and authentication settings stay in Netlify Identity. The app's password login does not add its own MFA; MFA needs a supported identity-provider configuration before claiming it is enabled. Avoid an office-IP restriction for an owner working on the road.

## Route preview

City suggestions use a bundled 2026 U.S. Census Places Gazetteer for the 50 states and D.C. For street or address suggestions, Netlify sends the partial address to Geoapify. The form labels street-only matches and explains that their route estimates use a street location. **Use my location** fills the pickup coordinates after the customer grants permission and the browser checks them against the Census national boundary. [Census Gazetteer](https://www.census.gov/geographies/reference-files/time-series/geo/gazetteer-files.html) · [Census boundary files](https://www2.census.gov/geo/tiger/GENZ2025/kml/) · [Geoapify autocomplete](https://apidocs.geoapify.com/docs/geocoding/address-autocomplete/).

Create a free Geoapify project, set its API key in Netlify as `GEOAPIFY_ROUTING_KEY` with **Functions** access in production, and redeploy. The function sends the selected coordinates to Geoapify when a customer selects **Preview route**. The quote form draws the road route in blue and shows estimated driving miles and time between the selected points. [Geoapify pricing and limits](https://www.geoapify.com/pricing/).

If routing is unavailable, the inline map shows the selected locations and **Open in Google Maps** gives customers driving directions. The quote sends the selected addresses or cities, or the pickup coordinates from **Use my location**. OpenFreeMap serves the basemap using OpenStreetMap data, with visible attribution. [OpenFreeMap](https://openfreemap.org/).
